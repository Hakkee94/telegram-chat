# Telegram Chat — тестовое задание React / GREEN-API

Минимальный веб-клиент Telegram: подключение через GREEN-API, создание чата по номеру телефона, отправка и получение текстовых сообщений. Интерфейс на русском, двухколоночный чат на компьютере и отдельные экраны списка/переписки на телефоне. Визуальная интерпретация веб-чата Telegram, не точная копия.

## Локальный запуск

Требуется Node.js 22.13 или новее и pnpm 10. В репозитории используется `pnpm-lock.yaml`.

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Откройте адрес, напечатанный dev-сервером. На обычной локальной машине это, как правило, http://localhost:5173. В управляемой среде команда может использовать другой порт.

```bash
pnpm exec tsc --noEmit
node --test tests/chat.test.mjs
pnpm build
```

`pnpm start` запускает собранный Worker локально через Wrangler. Сайт требует серверную часть `/api/green`; публикация только HTML-файлов без неё не поддерживается.

## Подключение Telegram

1. Создайте инстанс **Telegram** в https://console.green-api.com/ и авторизуйте аккаунт Telegram. Для полного сценария нужен второй аккаунт-получатель.
2. Дождитесь состояния `authorized`.
3. В настройках включите получение уведомлений о входящих сообщениях (`incomingWebhook: yes`). Для статусов доставки и прочтения включите уведомления об исходящих сообщениях и статусах (`outgoingMessageWebhook`, `outgoingAPIMessageWebhook`, `outgoingWebhook`).
4. Для HTTP API оставьте `webhookUrl` пустым. Не используйте инстанс одновременно с другим потребителем очереди, другой вкладкой чата или интеграцией: уведомления после обработки удаляются из общей очереди.
5. В приложении укажите `apiUrl`, `idInstance` и `apiTokenInstance` из карточки инстанса GREEN-API.
6. Подключитесь, введите номер получателя в международном формате (например, +7, +374 или +1), нажмите «Начать чат».
7. Напишите сообщение. Enter отправляет, Shift+Enter добавляет строку.
8. Ответьте с аккаунта получателя в Telegram: ответ появится автоматически.

Доступность получателя зависит от настроек поиска по телефону в Telegram, ограничений аккаунта и тарифа GREEN-API. Приложение не меняет настройки инстанса автоматически.

## Реализация

- React 19 + TypeScript, Vinext (совместимый с Next.js App Router), CSS/Tailwind, готовые доступные UI-примитивы и Lucide.
- `app/page.tsx`: экран подключения, список чатов, переписка, черновики, lifecycle запросов.
- `lib/chat/model.ts`: чистые функции нормализации номера, дедупликации, обработки событий и статусов.
- `lib/chat/api.ts`: типизированный клиент и отменяемая задержка повторов.
- `app/api/green/route.ts`: ограниченный same-origin proxy с разрешёнными методами/хостами, таймаутом и безопасными сообщениями об ошибках. Убирает зависимость браузера от CORS GREEN-API.
- `tests/chat.test.mjs`: тесты бизнес-логики и API-контрактов с подменённым HTTP transport; реальные сообщения тесты не отправляют.

### Поток данных

`getStateInstance` + `getSettings` → `checkAccount` (номер в канонический Telegram chatId) → `sendMessage`.

Один последовательный long-poll `receiveNotification` (25 секунд) → обработка → `deleteNotification`. При ошибках — увеличивающаяся задержка до 30 секунд. При выходе/размонтировании запросы отменяются. Повторно доставленные сообщения не дублируются. Служебные и неподдерживаемые события подтверждаются, но не выводятся пустыми сообщениями.

Исходящее сообщение сначала локально получает `sending`, затем `accepted` после ответа API. **Принятие API не означает доставку**. `delivered`, `read`, `failed` и `noAccount` обрабатываются отдельно. Ранний статус до завершения `sendMessage` сохраняется в памяти. При неоднозначной сетевой ошибке автоматическая повторная отправка не производится, чтобы не создавать дубли.

## Границы проекта

- Только текст; вложения, звонки и управление группами не входят в задание.
- Токен, чаты и черновики хранятся только в памяти вкладки. Выход или перезагрузка очищают их. История до текущей сессии не загружается.
- Подтверждённые уведомления удаляются из очереди GREEN-API. Это учебный клиент без долговременного архива сообщений.
- Одновременная работа нескольких вкладок с одним инстансом не поддерживается.
- Настройка токена в `.env` не требуется. Не коммитьте реальные токены или персональную переписку.
- Для обычного публичного промышленного размещения понадобятся собственная авторизация и ограничение частоты запросов. Текущая опубликованная версия закрыта для владельца.
- Опциональный WebMCP `stage_chat_message` только заполняет черновик; отправка остаётся отдельным действием пользователя.

## Проверка

Автоматически проверяются нормализация номеров, маршрутизация ответа в правильный чат, повторная доставка, текст с URL, неподдерживаемые события, статусы и ошибки, ограничения proxy, HTTP-контракты отправки/получения/ACK. TypeScript и production build проверяются отдельно.

**Реальный end-to-end обмен с Telegram не проверен без пользовательского инстанса.** Тесты transport не заменяют такую проверку. До отправки работодателю выполните сценарий из раздела подключения.
